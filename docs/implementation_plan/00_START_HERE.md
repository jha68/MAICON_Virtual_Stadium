# MAICON 2D 및 3D 시뮬레이터 구현계획

이 묶음은 다른 저장소와 새로운 에이전트가 이전 대화 없이 2D·3D 시뮬레이터를 구현하도록 만든 설계 계약이다. 경기 규칙, 데이터 형식, 파일 구조, 수치 알고리즘, 구현 순서, 검증 기준과 참고자료 발췌를 함께 제공한다. 시뮬레이터 실행 코드는 아직 포함하지 않는다.

자료 기준은 jha68/MAICON main의 7c414445fcf0302620b2c89f16ce2064f91ca753이다. archive 브랜치는 사용하지 않는다. 계획 버전은 1.0, 작성 기준일은 2026-11-07 한국시간이다.

## 1 목표와 확정한 설계

- 2D는 경기 규칙·계획·관측 집계·통신·마감·장애 복구를 빠르게 검증한다.
- 3D는 같은 규칙·평면 운동 엔진에 원근 RGB·가림·카메라/팬틸트·LiDAR·깊이 검증을 추가한다.
- Python3.10, 공통core, FastAPI, 2D NumPy/pygame-ce, 3D PyBullet DIRECT/TinyRenderer를 사용한다.
- ROS와 GPU는 핵심·2D·3D headless 필수 조건이 아니다. 실제 로봇 연결은 별도 adapter다.
- 3D v1은 실제 6륜 동역학·마찰·전복·정밀 레이저 광학을 재현하지 않는다. 그 기능을 구현 완료 조건에 추가하지 않는다.
- 현재 자료에서 미정인 규칙은 명시된 SIM 기본값으로 구현한다. 현장 답변을 기다리며 코어를 미완성으로 두지 않는다.
- 원본 자료의 이미지 없이도 직접 생성한 fixture 이미지로 완주할 수 있다. 실제 이미지·학습 모델은 교체 가능한 입력이다.

## 3 읽는 순서와 권위

처음부터 전체를 구현하는 에이전트는 00→01→02→05→06→03→04→07→08→09 순서로 읽고, 해당 설계 근거가 필요하면10을 대조한다. 구현 시작 전에11의 수정 내역과 한계도 읽는다.

2D 담당은 공통 문서01/02/05/06/07/08과03을 필수로 읽는다. 3D 담당은 같은 공통 문서와04를 읽고03의 공통 운동·충돌 인터페이스를 재사용한다. 문서 하나만 떼어 전달하지 말고 이 폴더 전체를 복사한다.

권위 규칙:
1. 현시점 source facts와 미확정 사항은01 및10을 기준으로 판단한다.
2. 시뮬레이터 내부 실행 순서·포트·정보경계는02가 원본이다.
3. HTTP wire 의미는05, 저장 설정 구조는contracts, 값의 의미와 기하 기본값은06이 원본이다.
4. 03/04는 해당 계약을 구현하는 방법이며 독자적인 점수·시간 규칙을 추가하지 않는다.
5. 07의 합격 기준을 만족해야 완료다. 다른 문서와 충돌하면 묵시적으로 선택하지 말고 계약과 시험을 함께 수정하고 결정 기록을 남긴다.

원본 자료는 2026-11-04 snapshot이며 최종 OT 규약과 다를 수 있다. 이 계획의 SIM 기본값은 대회 확정 규칙이 아니다. 실제 규약을 확보하면 별도 profile/version으로 반영한다.

## 4 처음 수행할 일

1. 대상 저장소의 지침과 기존 코드를 확인한다.
2. 계획 폴더 전체를 docs/implementation_plan/에 복사한다.
3. contracts와examples를 구현 저장소의 package resource와 sample directory에 복사한다.
4. 08의 M0 설치 spike와 schema validation부터 수행한다.
5. 01의 규칙과02의clock/queue를 먼저 구현한다.
6. 2D G1을 통과한 뒤 같은core에3D를 연결한다.
7. 구현 과정에서 실제 실행한 시험·결과만 IMPLEMENTATION_STATUS.md에 기록한다.

미확정 실제 SDK는 fake transport로 경계를 검증하고09의H단계를 별도로 남긴다. M0~M7/G0~G3는 실물이 없어도 완료할 수 있도록 설계했다.

## 5 성공의 의미

필수 결과는 실행 가능한 2D와3D, 공통 채점/API, 합성 센서, 참가팀 baseline,6개 프로세스 통합,시나리오·오류주입,재생·배치평가,설치·검증 증거다. 최고의 경기전략·최고인식모델·실물주행보장은 요구하지 않는다.

정답을 알고 움직이는 bot,정적GUI,임의점수표시,skip된3D렌더테스트로 완료를 대신할 수 없다. 참가팀과 평가자의 정보를 분리하고 같은 설정·입력의 결과를 재현할 수 있어야 한다.

이 묶음 자체의 검토·검증과 향후 구현체의 시험은 별개다. 11의 PASS는 계획 파일의 정합성과 인용·예시 검증을 뜻하며, 아직 만들지 않은 시뮬레이터가 실행 검증을 통과했다는 뜻이 아니다.

구현 중의 정정은 저장소 `docs/DECISIONS.md`에 기록했다. 원본 ZIP의 파일 해시는 `validation/MANIFEST.original.json`으로 보존하고, 현재 `MANIFEST.json`은 정정된 계획 파일을 검증한다. 구현·실행 증거의 현재 상태는 저장소 루트의 `IMPLEMENTATION_STATUS.md`가 담당한다.
