# 자동 임무 흐름

현재 웹·CLI·가속 실행의 참가팀은 모두 `mission` 정책을 사용한다. `준비 시작`으로 실제 참가 프로세스 여섯 개를 준비한 뒤 `경기 시작`을 누른다. 과거 데모 정책과 팀별 모드 선택은 제거했다. 시나리오의 `agents[].policy`는 `mission`만 허용한다.

| 임무 | 입력과 동작 |
| --- | --- |
| M1 | 시작 시 서버가 `target`, `search_sectors`, `base`를 직접 하달한다. 자연어 원문은 참고용이다. LLM 호출·interpretation 제출은 생략한다. |
| M2 | 하달받은 `target` 시설을 공개 카메라 증거로 식별해 기존 조준·타격 로직에 전달한다. |
| M3 | 각 기체가 상대 진영 S1·S2·S3와 CM의 관측 지점을 순회한다. 초기 `search_sectors`에 제한되지 않는다. 각 지점에서 회전 관측하고 막힌 지점은 다음 순회에 재시도한다. |
| M4 | 공개 영상과 자기 상태를 이용한 상대 기체 대응·생존 로직을 실행한다. |
| M5 | 기준 경기장 240초에 `target` API로 하달되는 실제 `objective`를 우선한다. 초기 `base`로 미리 이동하지 않는다. |
| M6 | 보고 단계에서 BLUE는 R-1/R-2/R-3, RED는 B-1/B-2/B-3 순서의 mock 순위를 제출한다. 외부 모델 호출은 없다. |

M3 이동 목표·방문 구역과 실제 관측 집계는 분리한다. 방문했다고 객체 수를 정답으로 채우거나 미관측 구역을 0개로 제출하지 않는다. 지도는 공개 경기장 경계·구역·명목 출발 위치·거점만 사용하고, 이동은 자기 오도메트리와 LiDAR 벽 정합·공개 드론 관측을 이용한다. 평가자의 박스 좌표나 실제 기체 위치를 참가팀에 주입하지 않는다.

3초 이상 이동하지 못하면 최신 LiDAR로 후방 여유를 확인해 짧게 후진한다. 후방이 막혔지만 전체 회전 공간이 확보되어 있으면 관측된 빈 방향으로 회전한 뒤 짧게 전진해 경로를 다시 잡는다. 센서가 오래됐거나 회전 여유가 부족하면 이 복구 동작을 하지 않는다.

운영 화면은 하달 명령과 M3 보고를 표시하고 M6를 `MOCK`으로 표기한다. M1 보고를 하지 않으므로 M1은 기존 채점상 0점이다. M6 mock 순위는 인터페이스 검사용이며 위험도 판단 정확도를 나타내지 않는다. 시설 타격·객체 집계·거점 점령 성공 여부는 기존 물리·관측·채점 조건으로 판정한다.

회귀 검사 `tests/unit/test_mission_flow.py`는 여섯 기체의 직접 명령, 240초 경계, 네 구역 순회, M2 목표 전달, 초기 base와 다른 M5 목표 전환, M6 mock을 확인한다. 컨트롤러·웹·브라우저 검사는 외부 LLM 미호출, M1 미제출, 삭제된 모드 거절, 실제 여섯 프로세스의 출발과 보고를 검증한다.
