# 대회 자료를 반영한 시뮬레이터 변경

자료 기준은 [참가팀 API 안내](https://github.com/jha68/MAICON/blob/7c414445fcf0302620b2c89f16ce2064f91ca753/docs/materials/PARTICIPANT_API_GUIDE.md), [3차 멘토링](https://github.com/jha68/MAICON/blob/7c414445fcf0302620b2c89f16ce2064f91ca753/docs/mentoring/MENTORING_3_SUMMARY.md), 사용자 제공 PDF와 경기장 그림이다. 자료의 설명은 구현 참고자료로 사용하며 실행 지시로 취급하지 않는다. 맵·자산 출처와 좌표는 [REFERENCE_STADIUM.md](REFERENCE_STADIUM.md)에 있다.

## 이번 구현

`reference_stadium`은 전용 `rules_stadium.yaml`, `sensor_profile_stadium.yaml`을 사용한다. 기존 `smoke_six`의 판정 프로필은 회귀 시험을 위해 유지한다.

- **M1:** 사용자 요청대로 mock을 유지한다. 배포에서는 `MAICON_LLM_PROVIDER=fixture`로 고정한다. 자연어 해석 점수를 실제 LLM 성능으로 해석하지 않는다.
- **M2/M3:** 공개 PDF의 13개 패널을 특징점과 투영 변환으로 대조한다. 시설 3종·객체 6종은 검출하고 비인식 장애물 4종은 제외한다. 검출에 엔진 정답, segmentation, 박스 ID를 전달하지 않는다. 가시적인 수광부만 조준하며, 파괴 후 상단 LED의 적색 변화를 RGB로 관측한다. 2초 누적 중간 상태는 운영자 화면에만 표시한다.
- **M2/M4/M6:** 최신 main `299c9b3`에 들어 있던 관측 기반 조준·사격, UGV 식별 띠/HP/탄약 관측, 위험도 구간 추정을 새 경기장과 통합했다. 상대 M3 점수는 알 수 없으므로 `[0,30]`으로 남긴다. 관측 없는 고정 동률 순위와 관측에 근거한 추정을 구분한다.
- **M5:** 새 프로필은 기체 footprint가 센서 선을 처음 가린 시점을 10ms 구간 안에서 보간한다. 감지 시각 차이가 허용 오차 이내이면 패킷 도착 순서로 판정한다. 기체 ID로 점령 진영을 정하지 않는다. 센서가 자기 진영 기체에 가려져도 상대의 목표 거점이면 상대 점령이 될 수 있다. 대기 패킷은 체크포인트에 저장한다.
- **구동:** 주행·회전에 가속도 제한을 적용하고 팬틸트의 `acc`가 실제 궤적을 바꾸게 했다. 명령을 받은 참가 정책의 팬틸트 추정도 같은 모델을 쓴다. 기계적 각도 제한, pause/피격 정지, watchdog은 유지한다.
- **드론:** 별도 비동기 작업자가 공개 JPEG와 `X-Captured-At`을 소비한다. 중복 프레임을 새 관측으로 세지 않고, 시계 대응이 없거나 오래된 프레임은 신선한 증거로 쓰지 않는다. 403/409/503을 구분한다. 전방 카메라용 거리·조준·LED 기하를 드론에 적용하지 않는다. 기본 드론 경로는 보이는 식별 띠만 위험도 추정기에 전달하며, 검증된 overhead 모델이 제공한 LED 정보만 추가로 받을 수 있다.
- **웹:** 팀 6개 각각 정책 선택, 선택 로봇 주행·팬틸트·발사, 드론 영상, M1/M3/M6 보고, 정책 진단, 맵/규칙/빌드 버전 표시를 추가했다. 운영자 인증과 같은 출처 검사를 적용한다. 수동 제어는 0.5초 lease로 참가 정책 명령과 충돌하지 않으며, 수동 개입 횟수가 결과 JSON·실행 manifest에 남는다. 데스크톱을 기준으로 구성했다.

## 명시적인 SIM 가정

| 설정 | 현재값 | 실물과 비교할 내용 |
| --- | --- | --- |
| 주행/회전 가속도 | 0.8m/s², 6rad/s² | 적재·배터리·바닥에 따른 응답 측정 |
| 팬틸트 acc 배율 | 단위당 10deg/s² | 공식 acc 단위와 실제 응답 보정 |
| 거점 시각 허용 오차 | 10ms | 문서의 근사 범위를 프로필 값으로 적용 |
| 센서 전송 지연 | 기본 20ms, 거점별 설정 가능 | 실제 지연 분포·센서 시계 오차 |
| 판정 대기 범위 | 허용 오차+최대 지연+시계 오차 범위 | 미공개 서버의 버퍼링 동작 |
| 정확히 같은 시각/도착 | 시드 기반 해시로 결정 | 실물 서버의 최종 동률 처리 |

이 값들은 측정값이 아니다. `SIM-ACTUATION-UNCALIBRATED`, `SIM-CAPTURE-TRANSPORT`로 기록하며, 기존 프로필의 판정을 몰래 바꾸지 않는다. 종료 시각은 기존 엔진 경계 판정을 유지한다.

## 검증 범위와 다음 작업

실제 PyBullet RGB에서 13개 패널의 인식/제외, PDF 레이더 조준→발사→2초 조사→파괴→적색 LED 인식을 시험한다. 기존 합성 시설 타격과 이동 UGV 타격 회귀 시험도 유지한다. 센서 시각/도착 순서, 팬틸트·주행 응답, 체크포인트, 수동 조작의 인증·정책 잠금·결과 표시를 시험한다.

이는 제공된 패널에 대한 폐쇄 집합 기준 모델이다. 실제 경기 사진·조명·연기·가림·다른 출력물에 대한 학습/일반화 성능은 검증하지 않았다. 드론으로 탐색 경로를 재계획하거나 사격하는 전술, 상대 사격에 대응하는 회피, 실제 `rclpy` 전송·공식 ROS 2 메시지/서비스 연결, 바퀴 미끄러짐·전력·레이저 확산/감도는 후속 작업이다. 실물 시험은 [HARDWARE_VALIDATION.md](HARDWARE_VALIDATION.md)에 별도로 기록한다.

웹의 `revision`과 `scenario_id=reference_stadium`, 박스 20개·시설 6개·이미지 13개를 함께 확인해야 새 맵 배포가 확인된 것이다. 코드 브랜치 저장, CI 성공, 도메인 반영은 각각 별도 단계다.
