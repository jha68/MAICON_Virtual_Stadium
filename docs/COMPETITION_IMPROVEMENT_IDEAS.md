# 대회 준비를 위한 후속 개선안

2026-11-12. 아래는 후속 구현의 설계 배경이다. 현재 관측 기반 공격 상태기계·공식 색상 LED·영상 위험도 추정·LLM 제공자 선택·시간 동기화/면 추적·공개 벽 위치 보정·카메라 보정 도구를 구현했다. 사용법과 검증 범위는 [후속 기능](FOLLOWUP_FEATURES.md)을 따른다. 실제 제공자 API·공식 인쇄물·실물 보정값은 별도 입력과 현장 검증이 필요하다.

## 1. M2·M4: 관측 기반 탐색·조준·발사 상태기계

현재 `PolicyDecision`에 발사 결정을 추가하고 컨트롤러에서 SDK fire를 연결하는 것이 출발점이다. `검색 → 후보 추적 → 조준 → 연속 조사 → 대기/재탐색` 상태를 명시한다.

- M2는 M1 해석에서 선택한 자기 지정표적을 우선 탐색한다. 카메라에서 시설 이미지와 수광부를 검출하고, 팬틸트로 화면 오차를 줄인다. 탐색·추적·조준의 confidence가 낮으면 발사하지 않는다.
- M4는 색 표식과 띠 수로 상대 진영을 확인하고 이동 표적을 추적한다. 아군·미확인 표적이 가리는 경우를 포함한 발사 금지 조건을 둔다. 시뮬레이터의 정답 pose나 객체 ID를 조준 입력으로 쓰지 않는다.
- 2초 연속 유효조사가 필요하므로, 발사 직후에도 영상 기반 조준을 유지한다. 반복 fire 호출로 조사시간을 연장하려 하지 않는다. `fired/empty/locked/reloading` 응답별로 전이하고, 응답 누락은 발사 여부 불명으로 처리한다. 실제 동작을 자동 재시도하여 탄약을 두 번 소비하지 않는다.
- 피격·pause·센서 만료는 제어를 중단시키고, resume 뒤에는 새 관측으로 재조준한다. M5 공개 시 목표거점 이동과 교전 중 무엇을 우선할지 정책으로 명시한다.

검증은 고정 시설 → 이동 UGV → 가림·아군 교차 → 센서 중단 순으로 확장한다. 영상만으로 조준하는 통합 시험에서 실제 engine 피격/시설 파괴를 평가한다. 탄약8발·조사2초·발광5초·재발사10초와 무적/잠금 경계도 함께 검사한다. 성공률, 명중당 탄약, 표적 발견부터 명중까지 시간, 오사 횟수를 기록한다.

## 2. 실제 LLM과 M6: 불확실도를 가진 증거를 축적

`FixtureLLM`은 통합 시험용으로 유지하고, 실제 제공자를 명시적으로 선택하는 설정을 추가한다. 기존 `LLMPort` 뒤에 주최측 최종 API 형식에 맞춘 어댑터를 두고 endpoint·model·timeout을 설정한다. 키는 환경 설정으로만 공급하고 요청·로그에 노출하지 않는다. 실패 시 fixture 결과로 조용히 바꾸지 말고 실패/대체 사용 여부를 결과에 표시한다.

M6는 LLM에게 호출부호 목록만 보내는 상태에서 다음 증거 모델로 발전시키는 것이 좋다.

| 관측 | 내부 추정 | 주의점 |
|---|---|---|
| 진영색·안테나 띠 | 상대 호출부호와 confidence | 다른 로봇의 이력을 합치지 않음 |
| 피격 상태 LED 변화 | HP 후보와 관측시각 | 가림·색 왜곡·이미 지난 사건을 반영 |
| 탄약 LED·발사 장면 | 잔여탄약 구간 또는 확률분포 | 한 발을 여러 프레임에서 중복 차감하지 않음 |
| 탐색·활동 이력 | 상대 M3 점수의 제한적 사전추정 | 상대의 실제 마지막 제출·점수를 안다고 가정하지 않음 |

상대별 위험도 `hp/4 + ammo/8 + m3/30`의 추정 구간/분포를 유지하고 순위와 신뢰도를 갱신한다. LLM은 관측 요약과 불확실도를 해석하고, 허용 호출부호와 JSON schema 검증을 거쳐 보고한다. 경기 중 최신 순위를 계속 준비하여 reporting 전환 때 느린 API를 기다리지 않고 제출할 수 있게 한다.

검증은 정답 위험도가 서로 다른 경기와 동점 경기를 구분한다. 관측 누락·식별 오류·LLM 지연/실패를 포함해 순위 일치율, M6 점수, 신뢰도 보정, 보고 마감 성공률을 기록한다. evaluator의 정답 HP/탄약/M3는 채점에만 사용하고 참가 알고리즘에는 주지 않는다.

## 3. M3: 시간 동기화와 박스·면 단위 추적

먼저 카메라 캡처 시각에 해당하는 odom·팬틸트 상태를 버퍼에서 보간한다. 지금처럼 오래된 영상에 최신 pose/LiDAR를 조합하면 로봇이 움직일 때 위치가 틀어진다. 카메라와 LiDAR의 높이·시야·TF 차이도 반영한다.

이후 단일 bearing+거리점을 누적하는 방식에서, LiDAR 선분/영상 모서리/다중시점으로 추정한 **박스 pose와 면 방향**을 추적하는 방식으로 확장한다. 같은 면을 다른 각도에서 보아도 하나로 연관하고, 같은 클래스가 붙은 서로 다른 면은 구분한다. 내부 track ID는 관측에서 생성하며 시뮬레이터의 정답 box ID를 사용하지 않는다.

위치 오차를 고려해 섹터 경계 부근은 귀속을 유보하고, 충분한 증거 뒤에 확정한다. 미관측 섹터와 실제로 확인한 빈 섹터를 구분하고, M3는 항상 현재 전체 snapshot으로 제출한다. SLAM 또는 영상/지도 정합으로 출발 pose 오차와 odom 누적 오차를 보정한다.

검증에는 같은 면 재방문, 동일 클래스 다중 면, 두 박스의 근접 배치, 가림, 시작 위치 오차, 지연 영상을 포함한다. 검출 정확도 외에 중복률·섹터 귀속률·섹터 종류/개수 완전일치율과 실제 M3 점수를 측정한다. 사용하지 않은 배치와 이미지 출처 그룹을 holdout으로 둔다.

## 4. 영상 단서: 공식 외형 프로필과 도메인 변화

실측 전에도 자료의 피격 LED 색(정상 파랑→초록→노랑→주황→빨강)을 차체와 분리된 표시부로 구현할 수 있다. 탄약8비트 LED와 진영/호출부호 표식도 각기 다른 장치로 유지한다. 관측 가능성은 거리·화각·가림에 따라 달라지도록 한다.

사용 권한이 있는 공식 인쇄물을 기존 import manifest에 경로·SHA256·출처·split_group과 함께 등록한다. 실제 카메라가 확보되면 보정판으로 intrinsics·왜곡·장착 TF를 측정하고 별도 실물 프로필로 저장한다. 사양의160도 표기만으로 렌더러의 수평화각과 초점거리를 확정하지 않는다.

밝기·화이트밸런스·블러·노출·왜곡·인쇄 크기·연기 농도를 변화시켜 시험한다. 깊이·segmentation·가시 mask 같은 정답은 비공개 데이터셋의 평가에만 쓴다. 실제 인쇄물·조명 조건에서 검증하기 전에는 합성 영상의 성공을 실물 성공으로 해석하지 않는다.

## 권장 구현 순서

1. 센서·카메라 보정 및 시간 동기화와 최소 정지/복구 경로를 안정화한다.
2. 공식 외형 단서와 고정 표적 M2를 연결한다.
3. 같은 면 재방문을 포함한 M3 위치·중복 집계를 보완하고 이동 표적 M4로 확장한다. M3는30점의 직접 득점이고 M4 공격은 상대 점수에 영향을 주는 전략이므로, 우선 M2/M3의 안정적인 성공을 확보하는 편이 좋다.
4. 축적된 교전/LED 증거와 실제 LLM을 M6에 연결한다. 실제 LLM API의 연결·timeout 시험은 앞 단계와 병행할 수 있다.

매 단계마다 대표 고정 fixture의 재현성과 미사용 랜덤 배치의 성능을 함께 기록한다. 최종 SDK가 제공되면 메시지 타입·QoS·현장 좌표와 실제 UGV에서 수행하는 team_node.py 경로를 검증한다.
